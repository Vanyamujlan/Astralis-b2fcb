# Единая система хранения аудитов Astralio

Папка `audits/` предназначена для централизованного, версионируемого и проверяемого хранения всех технических, продуктовых, рыночных и безопасностных аудитов проекта **Astralio**.

## Структура директории

```text
audits/
├── README.md                              # Правила ведения и структура системы аудитов
├── audit-history.md                       # Хронологический реестр всех проведённых аудитов
├── recommendations.md                     # Единый трекер задач, исправлений и идей развития
├── 2026-11-21_competitor-research.md      # Исследование Telegram-конкурентов (Этап 1 + Этап 2 верификации)
└── 2026-11-21_technical-audit.md          # Полный технический аудит текущей версии Astralio (v0.1.0)
```

## Обязательные правила ведения аудитов

1. **Отдельный файл для каждого нового аудита:**
   Каждый новый аудит сохраняется отдельным Markdown-файлом в папке `audits/` с префиксом даты в формате:
   `YYYY-MM-DD_<short-slug>.md` (например: `2026-12-01_security-audit.md`, `2026-12-15_monetization-audit.md`).
2. **Неизменяемость истории (Append-Only):**
   Запрещено удалять или перезаписывать ранее сохранённые отчёты. Если выводы старого отчёта пересматриваются, публикуется новый аудит или явный раздел верификации с сохранением исходного текста и указанием исправлений.
3. **Обязательное обновление индексных файлов:**
   После добавления каждого нового отчёта необходимо:
   - добавить новую запись в `audits/audit-history.md`;
   - при появлении новых дефектов, улучшений или гипотез обновить статусы и пункты в `audits/recommendations.md`.
4. **Доказательность и честность:**
   - Каждый технический вывод должен ссылаться на конкретный файл, функцию/класс, тест или результат фактической команды.
   - Каждый рыночный вывод должен ссылаться на конкретную страницу `t.me`, официальный сайт/оферту или независимый трекер. Неподтверждённые данные и гипотезы должны быть явно помечены.
5. **Безопасность (Zero Secrets Policy):**
   Категорически запрещено сохранять в отчётах `BOT_TOKEN`, `FIREBASE_PRIVATE_KEY`, `AI_API_KEY`, токены OAuth, пароли или персональные данные реальных пользователей.
